LLM inference hardware

Each hardware tab puts one capability against its two costs, purchase price and electrical power, first for a GPU, then for a complete computer, and then shows what that capability buys: memory sets the smartest model you can load, bandwidth the generation speed, compute the prefill speed. Higher and further left means more capability for the cost. All points are the same size; color gives the brand and shape the family.

Measurements

Horizontal axis

Method

  • Estimated, self-timed. Each coding agent ran the v2 protocol and took its own timestamps around every step: 0 log, 1 corpus, 2 read, 3 write, 4 and 5 ping, 6 write, 7 commit. The durations therefore include model thinking and tool overhead, not only generation. Token counts are bytes / 4, an estimate, not a tokenizer count.
  • Claude Code cloud sessions ran at max effort on Oct 30 2026. Haiku 5.5 is missing three cells because its sessions refused to push files containing model IDs.
  • Cursor composer-2.5 and grok-4.7 runs were launched simultaneously on Oct 29 2026.
  • Each histogram counts steps, so most model and cell pairs hold only a handful of values: read the shape with the count (n) in mind. Hover a bar for its values.
Columns

Method

  • Proxy-measured. Claude Code ran on a box and every API request went through a proxy that timed it and kept the API token counts. Time to first token, decode rate, and cache use come from those requests.
  • The box runs were at effort low on Oct 29 to 30 2026. Cells C0 to C3 reuse the prompt cache to different degrees; D is the long-decode cell, the only one where a decode rate is stored.
  • Excluded rows are hidden by default: a box freeze over 60 s, failed requests (class E3), and long outputs the model refused. Switch them on to see them in orange.

Method

  • Decode vs prefill. For each model and context size, decode speed comes from the long-decode (D) cells and prefill speed from the cache-miss (C0) and cache-hit (C2) cells of the box runs. Points are medians; bars span p25 to p75.
  • Prefill speed is end to end: prompt tokens (the prompt_tokens column: input + cache creation + cache read tokens) divided by time to first token. TTFT includes network, queueing and API overhead, so it is a lower bound on true prefill throughput. For a cache hit the effective prefill counts the cached tokens as processed.
  • Decode is decode_tps from the D cells; the same decode value is used for both series of a model and context.
Prefill axis

Concurrency

Per-session generation speed against per-session prompt work as the number of concurrent sessions N grows. Sonnet 5.5 is client-observed through the Anthropic API; the DeepSeek V4.1 Flash points are an InferenceX run on dedicated 4x H200.

Y axis

Method

Sonnet. claude-sonnet-5-5 via the Anthropic Messages API (streaming), adaptive thinking at default effort, max_tokens 16000, standard service tier. Tiers N = 1, 2, 4, 8, 16 concurrent sessions run sequentially; 31 sessions, each 10 turns. Each session starts with a unique ~60k-token prefix (a session nonce followed by public-domain Moby-Dick text, Project Gutenberg #2701) and each turn appends ~8k new tokens of the next excerpt plus a request for a ~500-word essay (~1k answer tokens); the assistant reply (including thinking blocks) is kept in history, so context grows from ~68k to ~151k tokens. Prompt caching: one ephemeral 5-minute cache breakpoint on the newest user block, so each turn reads the previous prefix from cache. Sessions start with a random 0-2 s stagger.

Metrics. Same formulas as the InferenceX reference: per-tier window from first request sent to last response finished; gen/session = output tokens / window / N; new prefill/session = (uncached input + cache-write tokens) / window / N; ingest/session = all prompt tokens / window / N; inst gen = output tokens / (last delta - first delta) per call; TTFT = first streamed content delta (includes thinking). The "p90" of rates is the slow tail (10th percentile); of TTFT it is the 90th percentile.

Caveats. Requests ran from a cloud box whose egress geolocates to Paris, FR (Cloudflare AS13335). API latency includes the network path and Anthropic's shared serving, so these are client-observed numbers, not hardware numbers, and are not directly comparable to the dedicated 4x H200 DeepSeek runs. Output tokens include thinking tokens.

429 handling. retry-after is honored, else exponential backoff; persistent 429 stops a tier and keeps what was measured. Counts are in the table. The http_other_errors column counts attempts that failed without an HTTP status (a dropped connection) and were retried; transport errors (a dropped stream or connection) are retried with backoff like 429s.

Discarded runs. Two earlier attempts are not in the tables. A first N=1 run used random words as filler and the model refused it (stop_reason refusal); it was replaced by the Moby-Dick text. A first N=16 run stopped after turn 1 when the server dropped two streams, before transport-error retries were added; N=16 was rerun in full. Their cost is included in the total spend.

Spend. Total measured spend for the sweep: 21.75 USD (about 19.5 EUR at 1 EUR = 1.1130 USD), run on 2026-10-30 between 09:38 and 09:55 Paris time (CET).

Observation. From N=1 to N=16, gen/session stays between 64 and 70 tok/s and TTFT median between 1.9 and 2.6 s, with 0 HTTP 429 at any tier, so the API did not saturate in this range, unlike the 4x H200 reference.

DeepSeek reference. InferenceX GitHub Actions run 39960029311, DeepSeek V4.1 Flash on 4x H200, vLLM v0.32.0, FP4, MTP; values taken from the run artifacts. N=128 is flagged saturated.

The runner and aggregator scripts are scripts/agentic/sonnet_concurrency_sweep.py and scripts/agentic/sonnet_concurrency_aggregate.py.
