LLM inference hardware

Each hardware tab puts one capability against its two costs, purchase price and electrical power, first for a GPU, then for a complete computer, and then shows what that capability buys: memory sets the smartest model you can load, bandwidth the generation speed, compute the prefill speed. Higher and further left means more capability for the cost. All points are the same size; color gives the brand and shape the family.

Measurements

Horizontal axis

Method

  • Estimated, self-timed. Each coding agent ran the v2 protocol and took its own timestamps around every step: 0 log, 1 corpus, 2 read, 3 write, 4 and 5 ping, 6 write, 7 commit. The durations therefore include model thinking and tool overhead, not only generation. Token counts are bytes / 4, an estimate, not a tokenizer count.
  • Claude Code cloud sessions ran at max effort on Oct 30 2026. Haiku 5.5 is missing three cells because its sessions refused to push files containing model IDs.
  • Cursor composer-2.5 and grok-4.7 runs were launched simultaneously on Oct 29 2026.
  • Each histogram counts steps, so most model and cell pairs hold only a handful of values: read the shape with the count (n) in mind. Hover a bar for its values.
Columns

Method

  • Proxy-measured. Claude Code ran on a box and every API request went through a proxy that timed it and kept the API token counts. Time to first token, decode rate, and cache use come from those requests.
  • The box runs were at effort low on Oct 29 to 30 2026. Cells C0 to C3 reuse the prompt cache to different degrees; D is the long-decode cell, the only one where a decode rate is stored.
  • Excluded rows are hidden by default: a box freeze over 60 s, failed requests (class E3), and long outputs the model refused. Switch them on to see them in orange.

Method

  • Decode vs prefill. For each model and context size, decode speed comes from the long-decode (D) cells and prefill speed from the cache-miss (C0) and cache-hit (C2) cells of the box runs. Points are medians; bars span p25 to p75.
  • Prefill speed is end to end: prompt tokens (the prompt_tokens column: input + cache creation + cache read tokens) divided by time to first token. TTFT includes network, queueing and API overhead, so it is a lower bound on true prefill throughput. For a cache hit the effective prefill counts the cached tokens as processed.
  • Decode is decode_tps from the D cells; the same decode value is used for both series of a model and context.
